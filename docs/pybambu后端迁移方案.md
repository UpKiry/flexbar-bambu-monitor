# pybambu 后端迁移方案

> 状态：迁移方案及离线原型进行中；本文不代表正式后端、跨平台打包或真机验收已经完成。基线：本项目 `d8efcc1d989dab17efb62f516046cfb7fc308af3`；上游快照 `e3c73139d443e9183ed2f804be30d2f2e53bbe66`。本地上游检出未确认是否为远端最新版本。

## 1. 目标、范围和证据

保留 FlexDesigner 插件、浏览器后台、按键展示和已有配置体验，用受控的独立 Python 子进程承载上游 pybambu，逐步替换现有云端监控实现。首个可发布里程碑只包含登录、选设备和只读云监控；打印控制、摄像头、FTP、局域网及历史文件均不纳入。独立原型先验证边界和打包，不修改现有用户路径，不把原型当成发布实现。

| 事项 | 已验证：代码或仓库检查 | 待验证 |
| --- | --- | --- |
| 宿主与展示 | `src/runtime.js` 注入认证、设备管理器，负责配置、消息和绘制；`src/printer/state-mapper.js`、`state-reducer.js` 定义状态及增量合并；现有设计记录真机验收尚未完成 | FlexDesigner 实际对子进程、文件权限和插件升级的行为；不同机型数据语义 |
| 上游边界 | pybambu 位于 `custom_components/bambu_lab/pybambu/`，不是本次发现的独立发行包；`bambu_cloud.py` 有登录/验证码方法；`bambu_client.py` 调用 Paho MQTT 和 `Device` 模型；入口直接导入客户端和云类 | 不依赖 Home Assistant 启动所需的完整依赖闭包、Python/Paho 兼容版本和线程安全 |
| 副作用 | `BambuClient.connect()` 会清理历史文件、探测媒体，默认缓存路径指向 `/config/www/media/ha-bambulab/...`；接收首条消息会启动切片设置云请求；订阅后请求版本和完整状态，watchdog 还会发布 `START_PUSH` | 上述副作用在云模式的触发条件、是否可关闭以及最小安全补丁；读取/连接不等同严格只订阅 |
| 安全存储 | macOS 使用 `security` 命令，写入内容通过标准输入传递并核对；Windows 后端尚未实现，不可用时有内存回退 | 真机钥匙串及 Windows 安全存储、权限、重启恢复和退出登录验证 |
| 平台与发布 | manifest 声明 macOS 10.15+、Windows 10+；现有 release workflow 在 Ubuntu 上构建一个插件包，Node 20；未见 Python 分发流程 | 可执行文件最低系统版本、架构、签名、公证、FlexCLI 保留文件与执行权限，以及 Windows 安全软件兼容性 |
| 许可与资源 | 上游根 `LICENSE` 为 MIT，要求随副本保留版权及许可；`const.py`、`utils.py`、`bambu_client.py` 通过文件路径读取 JSON、HMS 数据、证书等 | 每个打包依赖和资源的许可、冻结后路径与资源完整性 |

当前原型已在 macOS 的 Python 3.12 开发环境中导入固定上游快照。此结果不证明依赖闭包、发布产物或其他平台可用。

## 2. 架构与进程契约

```text
FlexDesigner → plugin.js → runtime.js → BackendAdapter ── stdin/stdout ── Python sidecar
                 │          │                 │                         ├─ 本地适配层
                 │          ├─ 配置/安全存储   │                         └─ 锁定的 pybambu
                 │          └─ 展示/按键       └─ 生命周期、限流、版本检查      └─ Bambu 云 HTTP/MQTT
                 └─ 127.0.0.1 管理页 → runtime.actions
```

Node 保留宿主生命周期、浏览器后台、绘制、非敏感配置及凭据存储，Python 负责具体云通信及状态转换。Node 只创建一个随插件生命周期启动的子进程，以绝对路径、`spawn` 参数数组和 `shell: false` 启动；不监听 TCP 端口，不把密钥放命令参数、环境变量、临时文件或日志。标准输入/输出仅供机器协议，诊断仅走受控 stderr；stderr 必须限制长度且经双方脱敏，禁止转发原始异常与上游日志。启动失败应明确显示后端不可用，不阻塞宿主；退出先请求 shutdown，超时终止并等待回收。禁用打印控制、相机和媒体，阻断其副作用；仅设 `host` 或 `enable_camera` 不能证明 FTP、缓存等都已关闭，须以测试证明补丁有效。

**建议协议 v1**：UTF-8 JSON Lines，每行一个 JSON 对象，最大 256 KiB，严格校验类型、字段和帧长，超限或非法帧视为协议故障；避免在 stdout 写任何其他内容。每次启动有随机 `sessionId` 和单调递增请求 `id`；初始化 `hello` 交换协议版本、构建版本、上游 commit 和能力集，主版本不匹配立即拒绝。请求 `{v:1,id,method,params}`，结果 `{v:1,id,result}` 或 `{v:1,id,error:{code,message,retryable}}`；主动事件 `{v:1,event,sessionId,seq,deviceId,data}`。密码、验证码、令牌只经私有管道传递，不能出现在错误和事件中；上游 callback 若来自 MQTT 线程，使用有界队列转入 Python 事件循环，再串行输出。状态事件可合并最新值，认证/错误不可丢；队列溢出标为状态失效并重新同步，禁止无界积压。

| 方法/事件 | v1 责任与语义 |
| --- | --- |
| `hello`、`shutdown` | 协商能力并完成优雅关闭；不接受未协商命令 |
| `auth.login`、`auth.submitCode`、`auth.cancel`、`auth.logout` | 明确登录状态和错误类别；取消或换区使旧请求失效；令牌仅在登录响应或恢复请求的私有通道流动，Node 存取系统安全存储 |
| `devices.list` | 返回字段白名单 `id/name/model/online`，适配层立即丢弃 `dev_access_code` 等敏感字段 |
| `monitor.start`、`monitor.stop`、`monitor.refresh` | 一次只监控选中设备；传区域、设备 ID、用户标识和令牌；`refresh` 仅允许审计过的状态查询且共享冷却 |
| `connection`、`snapshot`、`authState` | 含设备 ID、连接代次、seq 和接收时间；设备更换或重启后旧代次事件丢弃；错误只给固定枚举与安全文案 |

建议 Python 输出完整规范化 `snapshot`，Node 不再对其重复应用原始增量 reducer；必须明确未知值为 `null`、未知活动为 `unknown` 并保留可安全展示的原始状态串；不把未知数值转成零。模型覆盖现有 `activity/rawActivity`、进度、剩余分钟、任务名、喷嘴及热床当前/目标温度、层数、错误码、HMS、`lastReportAt` 和连接状态。Python 端要证明上游模型能够区分未提供、空值、陈旧值和实际零值；否则由适配层维护显式字段存在性及任务代次。网络断开保留最后快照但标记过期；切换设备清空状态；新任务清除任务相关旧字段。连接成功不等于设备在线，也不等于收到首次报告。

每个请求设超时并限制并发；超时取消本地等待，迟到结果按 ID 和代次丢弃，不自动重放登录或其他有副作用请求。Python 崩溃时拒绝所有未完成请求，断开状态并采用有上限、带抖动退避重启；恢复时仅重建可确认幂等的监控订阅，不能自动重复认证或无限重连。令牌过期时停止重试并要求重新登录。`pushall` 自动及手动刷新共享每设备至少 5 分钟冷却，重启后也不得绕过；上游连接时自动 `PUSH_ALL` 必须纳入同一策略，不能只限制 RPC。以真实机型验证后再调整。

## 3. 锁定上游与维护补丁

采用 vendoring：固定上游仓库 URL、完整 commit SHA 和引入目录，保留完整 MIT 版权与许可。当前已保存该 SHA 的 pybambu 源码快照与许可证，来源见 `vendor/ha-bambulab/UPSTREAM.json`；仅排除上游模拟数据目录，生产资源保留。后续还需补齐源文件清单和哈希、第三方许可证及本地补丁序列。与其从 `main` 安装或用户机器运行 `pip install`，发布构建只使用审查后的锁定快照与锁定 Python 依赖；锁定 Python 解释器、打包工具和所有传递依赖版本及平台文件哈希，依赖仓库采用可复现的锁定方式并输出 SBOM。包中 pybambu 与适配层分开维护，避免直接散改导致后续无法重放。

已见依赖包括 `paho-mqtt`、`requests`、`beautifulsoup4`、`python-dateutil`、Pillow；`cloudscraper` 和 `curl_cffi` 是可选导入，默认代码选择取决于环境。明确选择、锁定并验证一种传输机制，禁止环境中偶然存在的可选包改变行为；验证间接依赖和资源闭包，勿把此清单误当完整闭包。证书、耗材 JSON、HMS 压缩数据及 `const.py` 查找父级 manifest 的路径都要在冻结产物中测通；删除无用资源之前先证明相应代码不会访问。默认禁用上游原始响应、MQTT payload 和异常堆栈日志：`bambu_cloud.py` 和 `bambu_client.py` 存在记录响应或报文的代码，仅调整日志级别不足以作为长期保证。可维护最小本地补丁或包装器并由测试锁定。

升级流程：选定完整新 commit → 比较旧/新 pybambu、资源、依赖、许可证、默认网络及文件副作用 → 逐个重放本地补丁并审查安全变更 → 更新锁文件及哈希 → 自动契约、脱敏、离线回放与双平台打包测试 → 在目标机型/固件及两个区域完成约定真机回归 → 留存结果及差异后才更新基线。保留上一个已签名可用产物与锁文件，出问题可回退；不在线自动拉取或运行未审查上游代码。证书变化、Paho API、Cloudflare 和认证流程变化均作为升级阻断条件。

## 4. macOS / Windows 分发

首选按目标平台构建冻结的 Python sidecar（例如 PyInstaller，具体工具及 Python 版本由原型实测后锁定），不要求用户安装 Python；用独立干净构建机生成平台/架构产物，避免依赖系统 Python 或跨平台伪构建。优先评估 macOS arm64、x86_64 和 Windows x64；Windows arm64 的原生或仿真支持须单独验证后宣称。实际最低系统版本必须由解释器、原生依赖和打包工具共同决定：manifest 声明的 macOS 10.15/Windows 10 是兼容目标，不能据此声称当前方案可运行；若不支持，应先决定兼容构建或明确调整支持范围。

CI 将 Node 构建与各目标 sidecar 构建分开，在对应系统安装锁定依赖、运行测试，收集可执行文件、动态库和资源，再组装平台插件包；在最终包中包含上游与依赖许可证、SBOM、版本及哈希。验证 FlexCLI 能否包含二进制及资源、保留可执行位、插件安装路径是否可执行；如 macOS ZIP 解压丢位，须使用可验证且安全的安装方式，不依赖运行时提权。macOS 评估签名、公证及隔离属性；Windows 评估代码签名和 SmartScreen。不得承诺这些步骤已通过。

每个平台在无 Python、无开发依赖的干净用户账户安装最终 `.flexplugin`：校验真实产物哈希、启动握手、找资源、联网、退出与卸载，覆盖权限不足、路径含空格/非 ASCII、离线和升级回滚。优先随插件一起安装 sidecar，文件路径由受信任的插件目录拼接；不可从 PATH 查找同名可执行文件。发布前验证架构检测和版本匹配失败时的提示、文件签名及插件包完整性。具体平台发布格式、安装升级原子性和 FlexCLI 限制仍需原型验证。

## 5. 迁移顺序与切换门槛

1. **P0 独立原型**：针对固定 commit 建立独立进程、最小依赖及资源清单，实现握手、退出和模拟状态；审计并封堵上游默认网络/文件/命令副作用。产出双平台冻结包、威胁模型和真实宿主可启动证据。尚无此证据前不接入用户默认路径。
2. **P1 状态只读垂直切片**：先使用手写脱敏数据回放完整/增量状态，对照现有展示契约；再经受控账号验证云 MQTT、首次快照、断线恢复、冷却和设备切换。开关默认关闭，Node 原实现仍是唯一默认数据源，禁止同设备并行双连接作为默认行为。
3. **P2 认证与设备**：迁移登录、验证码、失败/取消/换区、设备列表和凭据恢复，按现有 `runtime.actions` 保持 UI 契约；验证上游国区手机号、全球邮箱和二次验证，不假设其与现有实现一致。安全存储不可用只用内存并提示；完成安全存储与迁移验证后才启用持久化。
4. **P3 集成与灰度**：在真实 FlexDesigner 和 Flexbar 使用一个后端开关作互斥切换；对每平台和支持机型运行验收清单。切换时先停止旧连接并等关闭，随后启动新进程；失败时显式回退旧路径并清理子进程。凭据格式或位置改变时用受控一次性迁移，验证写入成功后再删除旧凭据；禁止静默明文降级。
5. **P4 发布及退役**：只有验证矩阵、签名/许可、运维与回滚全通过后修改默认值；经过观察再单独决定删除旧实现。任何阶段失败保留旧版本插件和配置的回退路径，不把只通过模拟器视为真机完成。

## 6. 安全设计

- 云 TLS 保持证书与主机名验证；上游代码存在禁用本地 TLS 验证分支，不向云端或默认配置开放，局域网模式另行设计。冻结包内证书来源、有效性和更新策略需审查。
- 安全存储由 Node 统一负责。修复 macOS 命令参数暴露，采用可验证的不经命令行传秘密的系统 API；Windows 实现凭据管理器或用户作用域 DPAPI 并验证读写删除和 ACL。密钥不可用/解锁失败时只保留内存并提示重启须登录；不声称 Windows 已持久化。退出登录关闭连接、清空内存并报告安全存储删除失败；服务端撤销仅在实际支持时声明。
- 按能力白名单暴露方法：不开放任意 pybambu 方法、任意 MQTT publish、任意路径或主机、命令执行；对于上游连接期间隐式 publish、媒体探测、缓存、线程及云请求需要实测和必要补丁。只允许用户选择明确的区域、设备；限制帧长、速率及待处理请求数。
- 密码、验证码、token、授权头、设备接入码和完整设备响应不得进入 stdout 以外的日志、崩溃报告、临时文件或测试样本；即使 stdout 必须承载密钥，也仅限私有管道，禁止抓取或记录内容。Python 端禁止上游响应体/报文日志，Node 端所有诊断统一脱敏并使用固定错误映射。避免异常字符串夹带秘密，明确日志大小及保留策略。测试凭据使用手写假值。
- 子进程管道只供父子进程，降低本机攻击面，但不宣称隔离同一用户下有足够权限的恶意进程。沿用管理页回环绑定、随机令牌、Host/Origin 校验、CSP 和限速，并测试浏览器侧无法访问 sidecar。

## 8. 当前实施记录（2026-11-19）
