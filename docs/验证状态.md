## 自动刷新重写：唤醒盲窗与活性底线（2026-11-20）

用户反馈睡眠唤醒后设备停留在旧数据、不自动刷新。代码定位为三个叠加缺陷：字段/失活预算耗尽后周期兜底被待补字段永久暂停（自动刷新终局性停止）；睡眠期间 TCP 静默死亡后恢复请求打进死连接白白消耗预算，keepalive 检出前预算已耗尽；时钟回拨让 `at < lastRequestAt` / `at < waitingSince` 类判断永久封锁调度。本次按 [设备协议与状态模型](设备协议与状态模型.md) §3 重写自动刷新：

- 周期兜底（15 分钟 + 0～60 秒抖动）成为活性底线：不受预算与待补字段限制，预算耗尽只停止快速档提前重试，任何状态（明确 offline 除外）都会继续自动请求。
- manager 的 tick 间隔跳变（前向或回向 ≥30 秒）视为唤醒/时钟跳变盲窗：立即标旧全部观测、重置调度预算与五分钟节流、五秒宽限后强制全量同步，并 `recycle()` 立即重建 MQTT 连接。
- 同步不再受批次/失活预算门控（重连与唤醒都是盲窗）；失活恢复快速档两次上限保留；时钟小步回拨把被越过的时戳下修到当前时间重新计时。
- [cloud-mqtt.js](../src/cloud/cloud-mqtt.js) 新增 `recycle()`：等待旧连接关闭后立即重建、不走退避，认证失败不重建。

Node 20 执行 `npm test`（430 项全部通过，重复三轮稳定）、`npm run build`、`npm run plugin:validate` 均通过。回归覆盖唤醒后强制同步与冷却重置、盲窗立即标旧、小跳变不触发、大幅回拨按盲窗处理、预算耗尽后的周期兜底、重连同步与失活预算边界、时钟回拨不封锁、recycle 的立即重建/合并/退避中断/认证拒绝。

阶段结束时可把详细过程归档；本页始终保留仍有效的范围与未完成项。历史测试次数、旧的“待验收”或总体通过，均不能自动覆盖后续候选。
