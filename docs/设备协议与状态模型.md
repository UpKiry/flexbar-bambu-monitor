# 设备协议与状态模型

本文归一说明当前实现有效的设备协议、领域值、增量与时间语义；新增字段应沿此边界核对实现。
开发流程、安全约束和命令见 [开发指南](开发指南.md)，模块职责与数据流见 [架构设计](架构设计.md)，自动检查及真机待验项见 [验证状态](验证状态.md)。
本文不记录历史测试次数、开发过程，也不把社区资料或自动测试当作目标固件已验证的保证。

## 1. 设备列表与状态分层

绑定设备由 [cloud-api.js](../src/cloud/cloud-api.js) 的 `fetchDevices()` 适配为摘要；只有当前账号验证归属的设备才能监控。
摘要包含 `id`、`name`、`model`、`online`、`printStatus` 和 `nozzleDiameter`，不透传完整响应。
`online` 仅接受原始布尔值，保留 `true / false / null`；缺失或其他类型为未知，不能转为 false。
[runtime.js](../src/runtime.js) 的全局 `devicesFetchedAt: number | null` 记录列表成功获取时间，清会话时清空。
列表在线值只是该次获取的快照，不替代 MQTT 实时 presence；浏览器轮询本机快照也不是新设备报文。

| 层次 | 含义与入口 |
| --- | --- |
| broker 连接 | MQTT 传输与订阅是否可用，由 [cloud-mqtt.js](../src/cloud/cloud-mqtt.js) 维护。 |
| 打印机 presence | `unknown / syncing / online / offline / unresponsive`，由 [presence.js](../src/printer/presence.js) 维护。 |
| 打印活动 | `unknown / idle / preparing / printing / paused / finished / failed`，来自设备领域字段。 |
| 字段 freshness | 每项读数自己的观测时间与旧标记，不能以连接时间或其他字段时间替代。 |

## 2. MQTT 主题、报文白名单与事件

[cloud-mqtt.js](../src/cloud/cloud-mqtt.js) 只订阅并处理 `device/{DEVICE_ID}/report`，订阅 QoS 为 0。
设备 ID 不得包含 `/`、`+`、`#` 或控制字符；其他主题不进入当前设备状态链路。
目标主题的 Buffer 报文上限为 256 KiB；超长、JSON 无法解析、非对象及数组不进入领域处理。
合法 JSON 对象到达可更新 `lastMessageAt`，并不自动成为有效遥测。

- `print` 必须是非数组对象，且 `command` 缺省/空值或为 `push_status`、`pushall`，才传给 mapper。
- `info.module` 只提取支持的 AMS 模块身份，身份元数据可以独立于 `print` 合并。
- 报文有顶层 `event` 时，适配器走事件分支并返回，不继续解释同报文的 `print` / `info`。
- 仅支持 `event.event=client.connected` 与 `client.disconnected` 的 presence 语义；未知事件只算报文到达。

完整状态请求发布至 `device/{DEVICE_ID}/request`，QoS 为 1，正文固定为：

```json
{"pushing":{"sequence_id":"0","command":"pushall","version":1,"push_target":1}}
```

这是只读查询；提交成功仅表示 MQTT 客户端接受发送，不证明设备收到或响应。
查询回执本身不证明在线，必须含经 mapper 校验的有效领域打印遥测才构成在线证据。
连接、重连及退出的代次隔离由 [printer-manager.js](../src/printer/printer-manager.js) 负责，旧连接回调不能更新新设备。

## 3. presence、超时与有限恢复

| 证据或条件 | presence 结果 |
| --- | --- |
| 初始、broker 中断或订阅不可用 | `unknown`，不推断打印机离线。 |
| connected 且 subscribed | `syncing`；已有明确离线证据时仍为 `offline`。 |
| 目标主题 `client.connected` | `syncing`，等待遥测；事件本身不直接证明在线。 |
| 目标主题 `client.disconnected` | 明确 `offline`，停止自动查询。 |
| 有效领域打印遥测 | `online`，更新遥测时间并重置失活恢复预算。 |
| 等待同步或最后有效遥测后达到 120 秒 | `unresponsive`，不等同于明确离线。 |

有效遥测判定复用 [presence.js](../src/printer/presence.js) 的 `hasTelemetry()` 与 [state-mapper.js](../src/printer/state-mapper.js) 校验。
已知活动、有效进度/温度/风扇/层数、故障及有效 AMS 领域内容可构成证据，有效 0 也算；空 HMS 数组是有效的“无 HMS 项”报告。
空 `print`、未知活动、只有 raw、任务名称/ID、结构 ID、版本身份、info 和纯查询回执不能续期。
显式 null 可清空领域值，但 null 本身不能证明在线。

- `lastMessageAt`：目标主题可接受 JSON 对象到达时间，包括无遥测的消息。
- `lastTelemetryAt`：最后有效领域打印遥测时间，presence 超时以此及等待起点判断。
- `lastReportAt`：reducer 接受打印补丁的报告时间，可能含仅 raw 更新，不能代替在线证据。
- `changedAt / source / evidence`：presence 转换时间、来源和证据；恢复计数与下次请求时间也独立保存。

[runtime.js](../src/runtime.js) 周期调用各设备 manager 的 `tick()`，无新报文也推进超时；tick 间隔跳变同时驱动唤醒恢复（见下文唤醒与盲窗）。
断线、离线和无响应均保留最后读数，不补零，不将 `activity` 改为空闲；connected/disconnected 事件与唤醒盲窗会标旧已有观测。
完整状态请求由 [refresh-scheduler.js](../src/printer/refresh-scheduler.js) 统一调度，只有 connected + subscribed 且未明确 offline 时启用。
请求有四类来源，合并为同一次只读 `pushall`：

1. **同步（sync）**：订阅成功、重连或设备 connected 后等待五秒；缺失或标旧目标仍存在时请求，宽限期内自然上报补齐则跳过。
2. **字段补全（fields）**：在线期间，核心字段缺失或既有测量标旧持续 30 秒后请求补全；多个字段合并为一次。可选字段从未上报不触发，任务名、身份元数据和 raw 风扇不触发；AMS 按层级测量标记识别。
3. **失活恢复（recovery）**：等待同步或失活达到 120 秒后请求；每次失活快速档最多两次，有效遥测重置失活预算。
4. **周期兜底（periodic）**：每 15 分钟加 0～60 秒随机错峰请求一次全量。

活性底线：periodic 不看是否有待补字段，也不被任何预算阻止；预算耗尽只停止对应快速档的提前重试，不能永久停止自动刷新，明确 offline 除外。
无响应（unresponsive）不挡死同步与周期兜底；字段补全仍只在 online 时提前触发。

1. 快速档预算：每个未恢复字段批次最多自动尝试两次；其他字段的有效遥测、broker 重连和重复 connected 不重置它。对应字段重报或被领域合并明确移除后才释放该批次预算。请求发送不解除 stale，不修改观测时间；后续报文按既有增量规则逐字段恢复。
2. 同步不受批次或失活预算门控：broker 重连、设备 connected 和唤醒都是盲窗，每次（重）订阅最多换一次补全。同步如实计入失活计数，但不被其阻止；失活恢复快速档的两次上限仍然有效，重连不能重置。
3. 唤醒与盲窗：[printer-manager.js](../src/printer/printer-manager.js) 的 tick 间隔跳变（前向或回向达到 30 秒，阈值可注入）视为系统唤醒或时钟跳变：已有观测立即标旧，调度预算与五分钟节流重置，五秒宽限后强制一次全量同步（不看字段状态），并主动重建 MQTT 连接（`recycle()`）。小步时钟回拨由 scheduler 与 presence 把被越过的时戳下修到当前时间，冷却从回拨时刻重新起算，不允许永久封锁自动刷新。
4. 所有自动原因合并并至少间隔五分钟，与最近手动完整状态请求也至少隔五分钟；唤醒重置该间隔。初次连接补全不绕过冷却。发布失败仍可能已到达 broker，计入间隔和预算；底层冷却拒绝不消耗预算。

手动完整状态请求仍为同设备跨连接共享五秒冷却，开始尝试发送就计入冷却，不能用重连绕过。
手动请求推迟自动请求和周期兜底时间，不等于有效遥测，不重置失活或字段补全预算。
各预算在同设备 manager 的连接更换间保留，唤醒盲窗的 resume 是唯一例外（整体重置）；设备切换或 manager 销毁后重建，底层五秒冷却仍由进程按设备共享。
五秒、30 秒（含唤醒跳变阈值）、120 秒、五分钟及 15 分钟均为工程初始阈值，尚未由目标真机确认；来源与验证边界见 [验证状态](验证状态.md)。

## 4. 领域值、增量与任务切换

[state-mapper.js](../src/printer/state-mapper.js) 只解释当前报文实际出现的字段，[state-reducer.js](../src/printer/state-reducer.js) 合并历史，且不修改输入状态。

| 输入 | 领域与时间语义 |
| --- | --- |
| 字段缺失 | 不产生补丁，保留原值、原观测时间及旧标记。 |
| 显式 `null` | 支持清空的字段写为未知，可记录本次时间；不得转换成 0。 |
| 有效 `0` | 保留 0%、0℃、零分钟、零余量和已报告无错；不用 truthiness 判断读数。 |
| 非法类型、格式或越界 | 忽略无效领域更新，不钳位，不刷新原有效读数时间；允许的 raw 标量可另存。 |
| 未知枚举 | 按明确规则保留原始信息，不猜测含义。 |

`gcode_state` 去空白并忽略大小写：IDLE→idle，PREPARE/SLICING/INIT→preparing，RUNNING→printing，PAUSE→paused，FINISH→finished，FAILED→failed。
未知非空状态为 `unknown` 并保留 `rawActivity`；它不证明在线。
进度 `mc_percent` 接受有限数值或可解析非空数字串，范围 0..100；`mc_remaining_time` 为非负分钟。
`layer_num / total_layer_num` 当前接受有限数值；不能擅自用统一“正数才有效”规则替代各字段校验。
`subtask_name` 保存未截断的 `rawTaskName`，展示名最多 60 字符；任务身份比较不使用截断名。
`task_id` 接受正安全整数或非空字符串，数字 0 / 全零字符串仅为占位，不作为可用身份。

任务切换优先比较两端可用 `task_id`，否则比较未截断任务名；不能以进度下降推断新任务。
切换时清空旧任务进度、剩余时间、当前/总层数、任务名和身份及相应 freshness，再合并新补丁。
设备切换整体重置状态、presence 和机型相关展示；任务切换不应清掉同设备 AMS。
“完整快照”只由有效 `gcode_state + mc_percent + nozzle_temper + bed_temper` 组合启发式识别，仍待实机确认。
该标记不授权清空所有缺失字段；完整报告没带 AMS 或其他字段时仍须保留旧观测。

## 5. freshness：持续遥测与独立观测

普通字段在 `freshness.fields`，AMS 在对应层级保存 `{ at, stale }`；缺少标记表示没有有效更新证据。
时间必须有限、合法且不晚于当前时间；时钟回退不能把未来观测视为新鲜。
带 presence 的快照中，presence 必须为 `online`，且最后有效遥测距今小于 120 秒，才能将读数显示为当前可用。
有效遥测持续活跃时，`stale=false` 字段不再仅因自身年龄超过五分钟标旧；`at` 仍是它自己的实际观测时间。
这不意味着所有字段刚测量，也不能把其他字段的更新时间复制过来。
断线或失活已产生的 `stale=true` 必须由对应字段实际重报解除；其他字段活跃不能替它恢复。
唤醒、时钟跳变的盲窗立即标旧全部观测：睡眠期间的上报无法证明被收到，读数年龄未超 120 秒也不例外；解除仍只能靠对应字段实际重报。
同步、未知、无响应、离线时显示最后已知值并标旧，恢复连接本身不刷新字段。
无 presence 的兼容调用仍使用五分钟年龄判断；不能用兼容回退推断设备离线。
仅 AMS 身份到达不刷新打印 `lastReportAt / reportStale`；非法风扇 raw 更新不刷新百分比 freshness。
具体消费入口为 [presenter.js](../src/display/presenter.js) 的 `markIsFresh / fieldIsFresh`，后台与绘制应保持一致。
AMS 旧空槽证据的五分钟保护属于第 7 节的合并规则，不是恢复所有字段五分钟过期的旧策略。

## 6. 温度与风扇

Legacy 温度为 `nozzle_temper / nozzle_target_temper`、`bed_temper / bed_target_temper` 和 `chamber_temper`。
接受有限数值及可解析的非空数字串；0 与负环境温度可有效，缺失保留、null 清空、非法值不刷新。
新协议温度由 mapper 解包：低 16 位当前温度，高 16 位目标温度；腔温只采用当前温度。
支持 `print.device.bed_temp`、兼容 `device.bed.info.temp`、`device.ctc.info.temp` 及 `device.extruder.info[].temp`。
Packed 值必须是整数且 `0 <= v < 0xffffffff`；负值、越界、全 1 或格式错误保守忽略，不将编码猜成正常读数。
有效新字段覆盖同报文 legacy 映射；格式错误通常保留 legacy 映射，双喷头占位保护除外。
双喷头由同报文整数 `extruder.state` 第 4–7 位得到活动 ID，与 `info[].id` 唯一匹配，不能选数组首项。
`state` 低四位表示多喷头时先排除顶层 legacy 喷嘴占位；匹配缺失/歧义则不更新当前喷嘴读数，不借用历史选择。
新 airduct 角色随模式变化，目前不强行映射到 legacy 风扇；第二辅助风扇、门/顶盖与热端架未新增展示。

| 领域键 / 名称 | 原始字段 | 0..15 档位转换 |
| --- | --- | --- |
| `part` 部件冷却风扇 | `cooling_fan_speed` | `Math.round(v * 100 / 15)` |
| `auxiliary` 辅助部件冷却风扇 | `big_fan1_speed` | 同上 round |
| `chamber` 腔体排风扇 | `big_fan2_speed` | 同上 round |
| `heatbreak` 热端散热风扇 | `heatbreak_fan_speed` | `Math.floor(v * 100 / 15)` |

仅接受数字整数或十进制整数字符串；小数、布尔、十六进制、打包值及越界值不能作为 PWM 档位。
例如输入 1 时前三路为 7%，热端为 6%；热端 8→53%、10→66%、15→100%。
风扇单位是档位转换百分比，不是 RPM、直接百分比或 `fan_gear` 字节；本插件没有调速或十位档匹配选项。
热端采用 BambuHelper 普通模式但不沿用越界钳位；非法可接受标量留在 `rawFans`，不更新有效百分比及其时间。
热端仅在有效百分比存在时展示，包含 0%；未上报不按机型虚构占位读数。

## 7. 机型目录与 AMS

[model-catalog.json](../src/printer/model-catalog.json) 保留来源 URL/commit，官方 ID、产品名、别名共享能力 profile；[capabilities.js](../src/printer/capabilities.js) 按本次机型与领域值计算，不跨设备缓存。
目录覆盖 X1/X1 Carbon/X1E、A1/A1 mini/A2L、P1P/P1S/P2S、X2D、H2C/H2D/H2D Pro/H2S/H3C 和 N8，H2C 合并 O1C/O1C2。
A1/A1 mini/A2L 明确不展示腔温、辅助及腔体风扇，P1P/P1S 不展示腔温；占位零不能绕过限制。
P2S 允许腔温，A2L 的 AMS 为 generic，不能按 A 字头猜 Lite；N8 三项能力为 null，基本通道也依有效读数退化。
未知型号保留名称，只展示实际有效的已映射读数；能力允许不证明硬件已安装、读数实时或真机验收通过。

AMS 按 unit ID、slot ID、zone ID 独立合并，不能按数组位置识别；非负安全整数 ID 归一为字符串。
各层缺失保留、null 表示未知、显式空数组清空；非空数组全为非法项不能当明确空列表。
状态保留最多 64 单元，每单元最多 16 槽及 16 分区，避免异常报文无限扩张。
明确产品身份优先于匿名 `rawInfo`，明确元数据互相冲突则类型未知；有未知/清空 `rawInfo` 时不回退机型猜测。
`info.module` 白名单 `ams/<id>`、`ams_f1/<id>`、`n3f/<id>`、`n3s/<id>`、`n10a` / `n10a/<id>` 分别识别 AMS、Lite、2 Pro、HT、3H；模块显式 id 优先。
仅保存单元 ID 与规范产品名；不自动发送 `get_version`，身份识别依赖实际版本模块报告，迟到身份按同 ID 合并。
同 ID 明确更换产品型号会清理旧槽位、分区、rawInfo 及相关 freshness；身份缺失增量不清空已有身份。
`ams.ams[].info` 十六进制低四位类型为 1=AMS、2=Lite、3=2 Pro、4=HT、5=AMS_LITE_MIXED、6=ZMULTI_A、7=ZMULTI_B。
不能将 7 猜为 AMS 3H；无明确类型证据时仅目录 `f1` 机型允许 Lite 回退，不能覆盖未知 rawInfo。
AMS 3H 仅展示实际上报的九槽，不按类型虚构九份数据，也不凭槽数或单元 ID 猜商品名。

`tray_exist_bits` 按十六进制解析；旧全局掩码仅用于 unit 0..3、slot 0..3 的已知四槽布局，位号为 `unitId*4+slotId`。
AMS 3H、有 zones、高编号或多槽布局不得套旧掩码；不适用时槽位 `exists` 为未知。
新鲜空槽证据清除颜色、材质、余量等旧数据；不能仅因缺少槽对象就断言无耗材。
旧掩码仅在 `stale=false` 且年龄小于五分钟、无时钟回退等条件下约束后续元数据；过期/断线旧空槽不能阻挡新数据。
`tray_now` 保留 raw；兼容索引小于 80 时按四槽换算，80..253 为单元 ID/槽 0，其余为未知，不据此扩展九槽推断。
颜色仅接受八位十六进制；材质为实际报告文本，槽状态、AMS 状态保留 raw，不猜枚举。
余量只接受 0..100，0 有效，缺失保留，null 或 -1 为未知；AMS Lite 不显示余量，其他类型也须槽位实际读数。
`zone_info[]` 以 `zone_id` 合并 `temp / humidity_raw / dry_time`，分别为温度、0..100 湿度百分比、非负整数烘干分钟。
每个 zone、每个字段有独立 freshness；不平均为整箱读数、不借顶层占位值、不猜 zone 与槽的固定对应关系。

## 8. 故障原始信息与依据

`print_error / mc_print_error_code` 独立保留：null 为未知，数值或数字串 0 为已报告无错，非零码保留原始码字符串。
聚合 `errorCode` 优先非零 `printError`，再取非零 `printErrorCode`；非法输入不覆盖旧有效码。
`hms` 只保留 `code / attr / module` 原始字段，不做故障含义推断；空数组可表达已报告无 HMS 项，null 为未知。
未知码、原始 AMS 状态、未知活动与 raw 风扇不得编造解释；故障展示也要核对对应字段 freshness。
